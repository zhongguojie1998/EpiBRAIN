# Large Scale Variant Effect Screen Pipeline


## Pipeline Overview

Run the following scripts in sequence:

1. **prebuild_model** (Optional) - Package trained model for distributed deployment
2. **get_full_var_info** - Enrich GWAS summary statistics with genomic coordinates  
3. **init_tasks** - Initialize HDF5 storage and experiment data
4. **assign_tasks** - Distribute computation tasks across machines
5. **compute** - Execute variant effect predictions
6. **merge_results** - Consolidate results from distributed computation

## Data Structure

The pipeline uses HDF5 for storage:

```
res_file.h5
├── variants/               # Main variant table (sorted by index_key)
│   ├── index_key          # Unique identifier (chr:pos:ref:alt)
│   ├── rsid, chr, pos, ref, alt
│   └── finished           # Boolean completion status
├── results/
│   └── variant_effects    # Model predictions [n_variants × n_labels]
└── experiments/           # Per-experiment GWAS data
    └── {exp_name}/
        ├── index_key, z_score, n_sample
        └── reverse_map    # Allele orientation flag
```

## prebuild_model

### Purpose

Packages trained PyTorch model with tokenizer and config for distributed deployment. This optional, you can also build the model during computation runtime.

### Key Parameters

- `--model_chk`: Path to model checkpoint
- `--config`: Path to model configuration yaml file (use the autogenerated one in training log dir)
- `--output`: Output path for packaged model

## get_full_var_info

### Purpose

Enriches GWAS summary statistics by mapping rsIDs to genomic coordinates using VCF reference.

This script will automatically filtered out the following variants:

1. Not having enough information, like lacking ref/alt allele
2. Without valid identifier (only rsid supported)
3. Variants not on standard chromosome.
4. Variants not consistent with the standard vcf file 

For detailed processing info, refer to the log file

### Key Parameters

- `-s, --sum_stat_file`: GWAS summary statistics file, should at least have fields: `SNP`: the rsid of the variant (currently, only accept rsid as the standard identifier), `A1`: the alt nt, `A2`: the ref nt, `Z`: gwas z score, `N`: GWAS effective sample size
- `-v, --vcf_file`: Reference VCF file to get the full variant information, could fetch from [NCBI dbSNP](https://ftp.ncbi.nih.gov/snp/latest_release/VCF/GCF_000001405.40.gz)
- `-r, --rsidx_file`: rsidx index file, please **manually** generate it using rsidx (`rsidx index your_vcf_file rsidx_file`)
- `-o, --output_file`: Output enriched file
- `-a, --allow_ref_alt_reverse`: Allow ref/alt reversal. If enabled, when checking variant info consistency, if `A2` is actually the alt and `A1` is the ref, will still keep the variant (otherwise will be filtered). If reversed, in `experiments/{exp_name}/reverse_map` will be set to true to indicate
- `-p, --n_processes`: Number of parallel processes. When querying vcf database, how many workers working in parallel, can reduce the variant querying time. Especially useful when the variant number is big
- `-c, --chunk_size`: Number of chunk in one process, set a reasonable number so that the single process querying time is limited
- `--log_dir`: Output directory for logs (defaults to output file directory)
- `-e, --experiment_name`: Experiment name for log files (defaults to output file stem)

## init_tasks

### Purpose

Initializes HDF5 storage structure and loads experiment-specific GWAS data.

### Key Parameters

- `-s, --enriched_sumstats`: Enriched summary statistics file from `get_full_var_info`
- `-h5, --hdf5_file`: HDF5 storage file path
- `-l, --label_meta`: Label metadata CSV file. Use the one autogenerated when generating the data file for your model. Should be named as `{your_data_file_path}/label_meta.csv`.
- `-e, --experiment_name`: Unique GWAS experiment identifier. corresponding to {exp_name} in the data structure
- `--force`: Force recreate HDF5 file

## assign_tasks & compute

### Purpose

Distributes pending variants across compute resources and generates execution scripts. Compute the `mut` - `wt` for each tracks and sum over all positions.

### Key Parameters

- `-o, --output_dir`: Output directory for job scripts
- `-c, --compute_script`: Path to compute script (default: compute.py)
- `-g, --compute_config`: Compute configuration (format: `machine:device_count:batch_size:device_type` (gpu or cpu)), can be multiple
- `--force`: Force recompute all tasks
- `--abs_path`: If enabled, will write all the path in the script in absolute path

The following parameters are taken by `assign_tasks` and directly passed to each compute script

- `-h5, --hdf5_file`: HDF5 storage file to get all metadata
- `-m, --model_path`: Path to packaged model. When using `assign_tasks`, please first pack the model and pass the corresponding pkl file in `assign_tasks` (also directly passed to `compute`). If running `compute` alone, you can pass `--config_path`, if `config_path` is given, the model will be built during compute runtime. In this case, the `model_path` should be chk pt file instead of packaged pkl file
- `-p, --precision`: Numerical precision (float32/float64). **Important**, known issue is that due to some predictions/intermediates are very close to 0, the relative error for float32 could be big and will cause numerical instability. Use float64 will omit this issue, but the calculation time can be 10 times longer.
- `save_interval`: save intermediate results every given samples, can be useful when doing large scale screening

The following parameters are used by compute script but autogenerated by `assign_tasks`

- `-c, --chunk_indices`: Path to the numpy file with assigned task indices in the whole h5 file. Should be named as `chunk_{chunk_id}_indices.npy`
- `--batch_size`: Batch size for inference Autogenerated based on `compute_config` in `assign_tasks`. Or you can write it when only running compute.
- `--device`: Computation device (cpu/cuda:0/cuda:1/...). Autogenerated based on `compute_config` in `assign_tasks`. Or you can write it when only running compute.

## merge_results

### Purpose

Consolidates distributed computation results into main HDF5 file.

### Key Parameters

- `-h5, --hdf5_file`: Main HDF5 storage file
- `-c, --chunk_dir`: Directory containing chunk results (default: auto-detect)
- `--cleanup`: Remove chunk files after successful merge
- `--force`: Force merge even if some chunks failed validation
